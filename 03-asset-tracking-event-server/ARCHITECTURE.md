# Harness architecture

`harness/cli.ts` owns the participant process, source listener, subscriber sockets, scenario progression, deadlines and report. It opens the source listener before spawning, waits for the participant's source connection, then connects subscribers. READY, subscription ACKs, source barriers and same-stream GET_STATE fences establish causal ordering. No sleep determines correctness. The only scheduling delay paces an explicitly requested input rate.

`transport.ts` supplies real loopback TCP endpoints, incremental UTF-8 decoding, response framing, write deadlines, source READY/barriers and explicit split writes. Fragmented writes exercise framing but TCP can coalesce adjacent writes; unit tests also verify coalesced frames. Peer parsers reject malformed output, oversized lines and excessive response budgets. Responses and events are tracked separately to detect extra command replies.

`generator.ts` uses a seeded integer PRNG. Devices receive biased frequencies, GPS movements, declining batteries and ACTIVE/IDLE/OFFLINE transitions. Duplicate deliveries and adjacent out-of-order deliveries are reproducible. Batches provide throughput bursts; a configurable rate controls offered load. Fixed probes guarantee invalid-source, stale, equal-sequence, duplicate, property retention, unknown-device and malformed-command cases even for tiny workloads.

`model.ts` is an independent state oracle with global event ID history and per-device high-water marks. The controller calculates expected routing from its own subscription sets, never from participant output. The validator matches complete messages, counts missing/extra/corrupt deliveries and detects same-device reordering while allowing cross-device interleaving. Every final known device state is queried. This code is never imported into participant code.

Functional scenarios cover multiple subscriptions, fanout, idempotence, unsubscribe, no replay, subscriber disconnect/reconnect, and source disconnect/reconnect with preserved state. Sparse/intermediate state and post-reconnect state are checked before later events can mask defects. Cross-device reused IDs, stale-ID history, malformed command pipelines, Unicode identifiers and numeric boundaries supplement seeded traffic. Each batch is checked before proceeding. Final GET_STATE snapshots check devices without subscribers too. Optional stress first verifies ordinary delivery and then overloads a paused-reader connection while checking a healthy connection for the same device. No observed disconnect yields INCONCLUSIVE, because TCP saturation cannot be inferred from a fixed traffic count. A disconnect is evidence only: exact queue accounting still needs code review. The bound includes user-space runtime buffers as well as explicit application queues.

`harness/tests/` contains short-lived scripted socket fixtures, never a tracking service. They validate transport READY, barriers, reconnection, framing, subscriber parsing, deterministic failure paths, seeded generation, oracle decisions and validator faults independently. Pure decoder tests split Unicode frames at every byte position, independent of TCP coalescing. Lifecycle fixtures only exit or idle; they exercise failure reporting and cleanup without implementing the protocol. There is no runnable reference participant or end-to-end passing participant fixture. Consequently passing harness tests validates harness components; grading a real participant still requires the participant's executable.

Workload memory is bounded by CLI limits, event history and batch results. Latency samples and generated workload remain in memory for reporting; this is a local challenge harness, not an unbounded simulator daemon. Deadlines apply per operation; an explicit rate may intentionally make a whole run long.
